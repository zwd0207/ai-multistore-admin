# 紫鸟接入扩展路线

## 总原则

- 紫鸟负责店铺环境、账号、人员权限和受控启动。
- Naver/Coupang 官方 API 继续负责商品、订单、客服、物流、广告、销售和结算。
- 所有能力按公司、内部店铺、紫鸟店铺和内部用户隔离。
- 自动匹配只能生成候选，正式绑定必须人工确认。
- 本路线任何阶段都不允许保存原始响应、请求头、Token、Cookie、签名或平台密码。

## 阶段 A：文档和模型映射

### 复用

- ApiCapability、现有文档目录和总指挥决策记录。
- Store、DeviceEnvironment、ErpUser、ErpStoreMembership、ApiCredential。

### 扩展

- 冻结紫鸟字段字典、来源类型、只读/写入分类和风险等级。
- 明确公司级连接、外部店铺绑定和外部用户绑定合同。

### 禁止

- 不开发适配器。
- 不配置凭证。
- 不登录、不调用真实 API、不安装 Skill。

### 验收

- API、Skill、Demo、复用和安全边界文档齐全。
- 每项能力有确认状态和官方来源。
- 无重复 Store/Product/Order/用户模型建议。

### 回滚

- 删除本阶段文档即可；无数据库和运行时变化。

### 用户价值

- 避免重复开发，知道紫鸟能做什么、不能做什么。

## 阶段 B：本地 Mock 与适配器

### 复用

- 现有 service/adapter 模式、ApiCapability、SyncLog、Store onboarding、工作台。
- 完全虚构的本地数据库和测试身份。

### 扩展

- 新增一个紫鸟 provider 适配器接口，但不连接网络。
- Mock 能力限定为：公司、员工、店铺、设备、用户可访问店铺。
- 生成内部 Store ↔ 紫鸟店铺候选，不自动确认。
- 工作台显示“未连接/候选待确认/设备即将到期”的虚构状态。

### 禁止

- 不保存真实 API Key。
- 不新增第二套店铺、用户、同步或工作台。
- 不实现授权、设备、SSO 或页面写入。

### 验收

- 多公司、多店铺、多用户隔离。
- 同名店铺不能自动绑定。
- 前端扫描不到凭证字段。
- Mock 响应失败时不影响 Naver/Coupang 现有功能。

### 回滚

- 关闭 provider feature flag，删除虚构连接和候选数据。

### 用户价值

- 可以先看到最终操作流程和映射效果，不承担真实平台风险。

## 阶段 C：单店铺真实只读微测试

### 前置

- 负责人完成 `ziniao-manual-verification-checklist.md`。
- 紫鸟应用唯一、权限仅含批准只读接口。
- 公司级凭证模型和外部绑定模型经过安全审查。

### 复用

- 加密服务、会话/MFA/近期认证、店铺权限、SyncLog、ApiCapabilityTestResult、失败锁。

### 扩展

- 仅调用：公司 ID、店铺列表、员工列表、指定用户可访问店铺、设备查询。
- 单企业、单内部店铺、最多少量候选。
- 请求结果在内存中映射，只持久化白名单字段。
- 正式绑定由另一名复核人确认。

### 禁止

- 不调用 SSO Token、Webdriver、CLI、授权、设备或人员写接口。
- 不保存手机、平台密码、IP 原值、请求头或完整响应。

### 验收

- 真实只读调用数和端点白名单可证明。
- 跨店铺、跨用户、权限不足全部拒绝。
- API Key 轮换前后无明文落盘。
- 旧数据不覆盖新数据，重复读取幂等。

### 回滚

- 关闭紫鸟只读开关。
- 删除本测试批次新增的白名单字段和候选映射。
- 撤销应用只读权限或轮换凭证。

### 用户价值

- 验证系统能准确识别店铺、员工和设备，无需手工录入。

## 阶段 D：批量只读与失败隔离

### 复用

- SyncCheckpoint、租约、错峰、重试、自动读取异常中心和工作台。

### 扩展

- 每个企业连接独立凭证上下文。
- 每个店铺/资源独立 Checkpoint 和安全错误码。
- 周期读取店铺、设备、授权快照；工作台显示到期和权限漂移。
- 可选接收会员到期回调，前提是签名和重放规则已确认。

### 禁止

- 不批量启动店铺。
- 不自动修改权限、设备、标签或代理。
- 不用浏览器抓取替代平台 API。

### 验收

- 单店/单企业失败不影响其他范围。
- 到期、权限异常和凭证失效提示准确。
- 日志无隐私、凭证、完整 IP 或登录账号。
- 停止服务即停止调度。

### 回滚

- 全局和企业级开关关闭。
- Checkpoint 进入 disabled；只删除本 provider 快照，不影响 Store/订单。

### 用户价值

- 运营打开系统即可知道哪些店铺环境异常、设备将到期、员工权限不一致。

## 阶段 E：生成写入预览

### 复用

- 当前仓库发货 T18 的审批、候选哈希、批次版本、近期认证和审计模式。
- 现有操作审计和权限系统。

### 扩展

- 只生成以下写入预览：授权新增/删除、员工状态变更、标签或设备绑定建议。
- 预览包含目标企业、店铺、用户、当前值、建议值、权限影响和风险。
- 不调用紫鸟写接口。

### 禁止

- 不生成代理/IP 修改预览。
- 不生成自动购买、续费、删除店铺或密码变更。
- AI 只能解释和生成建议，不能签发审批。

### 验收

- 预览与最新只读状态绑定。
- 候选变化后旧预览失效。
- 普通运营看不到内部权限和敏感字段。

### 回滚

- 删除未执行预览和审批草稿；紫鸟无变化。

### 用户价值

- 管理员可以先看清改动影响，减少错店和错人授权。

## 阶段 F：人工审批后的受控写入

### 前置

- 每个写接口单独批准，不因阶段完成自动开放。
- 完成真实只读稳定期、备份/回滚演练、幂等和未知结果处理。

### 复用

- MFA、近期认证、双人复核、一次性审批令牌、原子 attempt、unknown/reconcile、安全审计。

### 可评估的首个写入

- 单企业、单店铺、单用户的一次授权新增或删除。
- 两次权威只读预检必须一致。
- 执行前后都重新核对店铺、用户和权限。

### 禁止

- 批量写入、定时写入、AI 自动写入。
- 创建/删除店铺、购买/续费设备、修改代理/IP、平台页面提交。
- `unknown` 结果自动重发。

### 验收

- 三重写开关默认关闭。
- 两个并发请求最多一个执行。
- 超时/断连进入 unknown，只能只读 reconcile。
- 审计只包含哈希、目标范围、动作、时间、结果和原因码。

### 回滚

- 关闭写开关，撤销未消费审批。
- 只读 reconcile 确认实际状态。
- 需要反向操作时必须重新预览、重新审批，不能自动补偿。

### 用户价值

- 在明确风险和人工控制下减少少量重复权限操作。

## 推荐的第一项最小安全扩展任务

**B1：紫鸟店铺发现与人工匹配 Mock。**

范围：

- 完全虚构公司、员工、店铺和设备数据。
- 使用现有 Store、DeviceEnvironment、ErpUser、ErpStoreMembership、ApiCapability、SyncLog 和 Dashboard。
- 输出候选匹配，不自动确认。
- 只做本地适配器合同和测试。
- 不新增真实凭证、不连接紫鸟、不启动店铺、不调用写入。

这是下一阶段风险最低、复用率最高、对最终产品形态最有帮助的任务。
