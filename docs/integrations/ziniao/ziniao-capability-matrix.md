## 2. 最有价值的 10 项能力

1. 发现公司全部紫鸟店铺。
2. 建立内部 Store 与紫鸟 store ID 的人工确认绑定。
3. 识别店铺所属平台、站点和标签。
4. 检查店铺是否绑定设备及设备是否可用。
5. 提醒设备/套餐即将到期。
6. 核对员工可访问店铺范围。
7. 对比内部 RBAC 与紫鸟授权差异。
8. 在工作台显示紫鸟环境健康状态。
9. 未来经审批一键打开正确店铺。
10. API 缺失时提供受控、可审计的人工浏览器入口。

前 8 项可以先做结构化只读；第 9、10 项属于高风险后置能力。

## 3. 紫鸟可以减少的人工工作

- 手工登记紫鸟店铺 ID、平台和标签。
- 逐店核对员工授权范围。
- 逐店检查设备绑定、套餐和到期时间。
- 在多个系统之间反复确认“这个店铺应该由谁操作”。
- 发现 API 异常后再手工寻找正确紫鸟店铺入口。
- 管理员查看权限漂移和环境异常。

## 4. 紫鸟不能替代的能力

| 能力 | 原因 | 继续使用 |
|---|---|---|
| Naver 商品、选项、库存 | 紫鸟公开 ERP API 未提供 Naver 商品结构化数据 | Naver 官方 API |
| Naver 订单、收件、物流 | 同上；浏览器页面读取不能当稳定 API | Naver 官方 API |
| Naver 客服咨询/回复 | 未找到 Naver 专用 Skill 或正式紫鸟结构化 API | Naver 官方 API + 人工确认 |
| Coupang 商品/订单/销售/结算 | 未找到 Coupang 专用 Skill 或正式紫鸟结构化 API | Coupang 官方 API |
| 平台广告和结算 | SkillHub 主要是 Amazon/Temu 等，不证明支持 Naver/Coupang | 对应平台 API |
| 平台写入幂等和事务 | 浏览器点击无法提供官方 API 的确定性语义 | 官方平台 API + 受控审批 |

## 5. 只适合作为页面操作的能力

- 打开/关闭紫鸟店铺窗口。
- 页面导航、截图、下载报表。
- 页面评论、广告、Listing 或库存操作。
- CLI 自然语言执行跨境运营任务。

这些能力的页面结构、登录态、验证码和平台风控都会变化，不适合作为核心数据库的权威数据源。

## 6. 必须保留人工确认

- 内部店铺与紫鸟店铺的正式绑定。
- 员工/角色/店铺授权的任何变更。
- 设备购买、续费、绑定、解绑和代理修改。
- 获取并消费 SSO Token、打开店铺。
- 浏览器页面提交、文件上传和平台写入。
- 截图证据的查看、下载和归档。
- AI 生成的操作建议和写入预览。

## 7. 风险优先级

| 风险等级 | 能力 |
|---|---|
| 低 | 公司 ID、标签列表、部门列表等低敏只读元数据 |
| 中 | 店铺、员工、设备和授权只读快照；第三方选品和图片能力 |
| 高 | Token、SSO、Webdriver、CLI、员工/店铺/设备/权限写入、截图证据 |

## 8. 阶段结论

紫鸟最适合成为“店铺环境与权限控制平面”，而不是 Naver/Coupang 业务数据平面。

首期价值应聚焦：发现、绑定、设备健康、人员可见范围和工作台提醒。平台业务数据继续由现有官方 API 负责。
