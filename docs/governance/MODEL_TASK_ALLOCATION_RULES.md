# 模型任务分配核心准则

## 总指挥：上下文与交付负责人

总指挥不是第四个执行模型，负责维护项目唯一事实并决定任务流向：

- 每轮先读取 `docs/PROJECT_CONTROL.md`、`docs/TASK_HANDOFF.md` 和 `docs/DECISION_LOG.md`。
- 将需求压缩成最小必要上下文，再派给 Sol、Terra 或 Luna。
- 负责工作树、集成分支、验收结果和阻塞项，不让执行模型各自维护不同版本的项目事实。
- 一个结果只有经过总指挥验证并写入 `docs/PROJECT_CONTROL.md` 后，才算项目已接受。
- 默认不把完整聊天记录和全部 Phase 文档发送给执行模型。

总指挥优先自行完成低 Token 的状态检查、分支核对和结果汇总；核心工程交给 Terra，高风险决策交给 Sol，低风险界面与批量工作交给 Luna。

本文件是项目任务派发的强制规则。目标是在保证质量和安全的前提下，合理使用 Token，不浪费高等级模型算力。

## 固定角色

### Sol：项目总监工

只负责高难度、高风险和跨模块工作：

- 产品方向、系统架构和重大边界决策。
- 权限、隐私、真实平台写入、资金和生产安全审查。
- 跨前后端、跨工作树的大版本方案与最终验收。
- Terra 无法解决的复杂故障和关键第二意见。

禁止把批量改文案、简单页面调整、常规测试和重复实现交给 Sol。

### Terra：项目副总监

作为工程主力，负责中高难度且边界已经明确的工作：

- 后端、数据库、接口和业务状态机实现。
- 前端核心工作流、跨模块联调和复杂问题修复。
- 权限规则落地、测试补齐和完整验证。
- 将 Sol 的方案拆解成可交付代码。

遇到未决架构、安全边界或真实平台高风险决策时，必须停止猜测并上报总指挥，由 Sol 决策。

### Luna：打工仔

只负责低风险、清晰、重复和可快速验收的工作：

- 已有设计下的页面实现、文案、样式和移动端适配。
- 测试数据、客服模板、批量整理和机械性修改。
- 已稳定接口的前端接线与基础构建检查。
- 不涉及核心业务决策的文档整理。

禁止 Luna 独立设计系统架构、权限模型、生产会话、真实平台写入或隐私边界。

## 派发前强制分级

总指挥每次派发前必须判断：

1. 是否涉及真实平台写入、隐私、权限、资金或生产安全？涉及则由 Sol 定边界，Terra 实现。
2. 是否需要跨模块设计或会影响长期架构？需要则先交 Sol。
3. 边界是否已经明确，主要工作是否为工程落地？是则交 Terra。
4. 是否为低风险、重复、批量、样式或文案任务？是则交 Luna。

无法明确归类时，默认交 Terra 做初步分析；不得直接使用 Sol 完成全部工作。

## Token 与并发规则

- 优先使用能可靠完成任务的最低等级模型。
- Sol 不重复阅读 Terra、Luna 已经验证过的全部实现，只读取决策摘要、变更范围和失败证据。
- Terra、Luna 只接收完成任务所需的边界、接口和验收标准，不发送无关历史资料。
- 可并行任务必须文件边界清晰；存在接口依赖时，先由上游完成合同，再启动下游。
- 同一问题连续失败两次或出现边界冲突时停止消耗 Token，升级给总指挥重新分配。
- 每个任务只输出 `STATUS / BRANCH / COMMIT / TESTS / BLOCKER`，除非总指挥要求详细报告。

## 推荐工作链

```text
Sol 定方向和高风险边界
        ↓
Terra 完成核心工程实现
        ↓
Luna 完成低风险界面、文案和批量工作
        ↓
Terra 完成联调与完整验证
        ↓
Sol 只在重大版本或高风险功能上做最终验收
```

## 不得违反的原则

- 不因 Sol 能力强就让 Sol 承担所有任务。
- 不因 Luna 成本低就让 Luna 处理高风险核心逻辑。
- 不让多个模型重复实现同一功能。
- 不在上游合同未完成时让下游凭猜测开发。
- 模型选择以任务难度和风险为准，不以当前哪个任务框空闲为准。
