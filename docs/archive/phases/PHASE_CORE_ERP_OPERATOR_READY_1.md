# Core-ERP-Operator-Ready-1 运营试用交付

## 交付口径

本阶段目标是让普通运营可以受控试用多店铺电商管理后台。系统优先展示本地 ERP 已保存记录、官方 API 能力和本地辅助功能。受控平台写入已按 Naver 官方接口开放，但只限人工确认后的 Naver 发货回填和人工客服回复。

## 每天使用顺序

1. 打开首页工作台，先看“全店铺运营总览”。
2. 先处理待发货、异常订单、库存预警。
3. 某个指标显示“?”时，表示系统无法确认该店铺的平台真实数据，不是 0。
4. 看到“IP 白名单未通过”时，先处理平台开放平台或卖家中心白名单，不要把订单数当成 0。
5. 看到“API 资料未配置完整”时，到“店铺管理”补齐对应店铺的 API 资料。
6. 进入发货辅助后，先做人工核对、导出表格、导入物流单号匹配；确认无误后才可提交 Naver 发货回填。

## Naver 订单模块

1. 在顶部选择当前 Naver 店铺。
2. 进入“订单管理”，点击“手动批量刷新”。
3. 系统读取 Naver 官方订单接口，并把订单业务字段写入本地 ERP。
4. 刷新成功后，订单列表可按新订单、待发货、已发货、取消、退货、换货和异常订单筛选。
5. 订单详情里可以复制收件信息、查看数据来源、保存本地内部备注。
6. 订单页不直接处理平台取消、退货、换货；需要人工到平台后台处理。
7. 需要发货回填时，从订单页进入“发货辅助”，导入物流单号并人工确认后提交 Naver 发货回填。

## Naver 客服消息模块

1. 在顶部选择当前 Naver 店铺。
2. 进入“平台消息”，点击“同步平台消息”。
3. 系统读取 Naver 官方客服消息接口，并把消息写入本地 ERP。
4. 消息列表可按平台、状态、紧急程度和关键词筛选。
5. 回复前先保存或核对本地草稿。
6. 提交到 Naver 前必须勾选“人工确认发送”。
7. Coupang / Gmarket 消息仍是本地入口，未接入真实平台消息同步。

## 明确不会自动做的事

- 不会自动回填 Naver / Coupang 发货；Naver 发货回填只能由人工确认后提交。
- 不会自动修改平台库存。
- 不会自动修改平台价格。
- 不会自动上下架商品。
- 不会自动回复客户；Naver 客服回复只能由人工确认后提交。
- 不会自动提交申诉。
- 不会自动发送邮件。

## 交付前检查

在系统设置中打开“交付检查”：

- 后端服务：应显示通过。
- 当前数据源：运营试用应使用 backend，也就是读取本地保存记录。
- 受控平台写入：必须显示 Naver 受控开放。
- 店铺状态：允许存在“?”，但运营必须知道“?”表示无法确认，不是 0。
- IP 白名单：如有阻断，需要单独处理白名单或权限。
- 备份状态：交接前建议先运行备份脚本。

## 启动和备份

一键启动或重启：

```powershell
.\scripts\operator-start.ps1
```

创建本地 DB 备份：

```powershell
.\scripts\operator-db-backup.ps1
```

命令行交付检查：

```powershell
node .\scripts\operator-readiness-check.mjs
```

## 安全边界

`REAL_API_WRITE_ENABLED` 必须保持 `false`，用于关闭通用平台写入开关。允许的真实平台写入只走受控操作门禁：Naver 发货回填和 Naver 人工客服回复。

手动同步只允许读取平台并写入本地 ERP。改价、改库存、自动客服、自动申诉、Coupang 写回、Gmarket 写回仍未开放。真实平台写入不得保存 token、secret、Authorization header、签名或平台原始响应。
