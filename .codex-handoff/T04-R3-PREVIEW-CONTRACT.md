# T04-R3 Naver 订单预览合同

## 总指挥决定

1. `Naver 技术预览` 永久只返回无完整隐私的摘要。
2. `授权运营订单接口 /orders/operations` 是运营人员查看完整收件信息的唯一页面接口。
3. 技术预览与系统内部订单记录必须使用两份不同的数据对象，禁止继续共用一份 `detail_preview`。
4. 本决定不恢复旧的“运营订单列表隐藏完整收件信息”规则。授权运营人员仍可在订单处理页面直接查看完整收件信息。

## 技术预览允许返回

- 店铺 ID、平台、同步状态、数量、时间范围和错误代码。
- 订单号与商品订单号的不可逆哈希，禁止完整号码。
- 商品、规格、数量、金额、订单状态、配送状态和申诉状态。
- 已脱敏姓名、电话末四位和买家 ID 哈希。
- `field_availability` 布尔值，用来说明收件姓名、电话、地址、邮编、物流公司和运单字段是否存在。
- `raw_response_saved=false`、`privacy_fields_redacted=true`、`orders_written` 等安全状态。

## 技术预览禁止返回

- 完整平台订单号和完整商品订单号。
- 完整买家姓名、买家电话。
- 完整收件人姓名、电话、地址、邮编和配送备注。
- 完整物流单号以及平台原始响应。
- Token、密钥、Authorization、请求头和签名。

## complete_field_preview 合同

- 保留 `requested`、`preview_only`、`available`、`field_availability`、安全状态和保存计划。
- `field_availability` 只能返回布尔值，不得返回对应原值。
- 删除或保持为空 `complete_fields`，不得借此返回完整订单号、姓名、电话、地址、邮编或物流单号。
- `detail_preview` 可以包含上述允许的脱敏摘要，但不得依赖它取得完整业务字段。

## 系统内部订单记录

- 从 Naver 原始详情先构造仅在服务端内存中使用的内部履约记录。
- 内部履约记录可以包含完整平台订单号以及发货所需的收件人姓名、电话、邮编、地址和配送备注。
- `real_sync=true` 时，由内部履约记录写入受控订单表；不得从已经脱敏的技术预览反向恢复数据。
- 原始平台响应不得保存，内部履约记录不得写入同步日志、错误日志或预览响应。
- 完整买家姓名和买家电话不是仓库发货必需字段，本阶段不得因技术预览需求新增保存；确有独立业务需求时另行审批。

## 授权运营订单接口

- `/orders/operations` 在真实身份、店铺范围和 `recipient_pii.view` 权限通过后，返回完整收件人姓名、电话、邮编、地址和配送备注。
- 无权限、跨店铺或普通摘要接口不得返回这些字段。

## 必须通过的测试

1. 上游响应包含完整隐私测试值时，技术预览的整个响应中找不到这些原值和完整订单号。
2. `complete_field_preview` 只返回字段存在性，不返回完整值。
3. `real_sync=true` 后，授权 `/orders/operations` 能读取保存的完整收件字段。
4. 无权限和跨店铺请求返回拒绝，响应不包含完整收件字段。
5. 同步日志、错误信息和操作日志不包含完整姓名、电话、地址、邮编和原始响应。
6. 仓库专项测试与 `verify_all.py` 全部通过。

执行时保留当前未提交修改，在此基础上完成数据对象拆分，不得只删除测试断言来换取通过。
