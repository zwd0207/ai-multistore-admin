## Delivered Workflow

1. Create a persistent warehouse batch from selected same-store/platform orders.
2. Block orders already held by any active batch, with both service validation and a database active-lock unique constraint.
3. Generate a warehouse XLSX in memory after operator approval and privacy acknowledgement.
4. Include only required warehouse fields in that XLSX: batch/platform/order references/SKU/warehouse code/product/quantity/recipient/phone/zip/address/delivery memo plus return columns.
5. Keep recipient PII out of batch rows, import rows, status events and returned audit-shaped payloads.
6. Parse warehouse return XLSX and persist the import plus normal, needs-confirmation and blocked states.
7. Confirm acceptable rows with an operator action, write local `DISPATCHED` evidence, then permit the Naver writeback step.
8. Require explicit manual approval, final confirmation, authorized operator role and `real_api_call_requested=true` before a real platform call.
9. Persist batch completion/partial failure state and each row's platform result/failure reason.
