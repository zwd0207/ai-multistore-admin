# Codex Project Entry Rules

This repository uses a commander-led workflow. Before planning, editing, reviewing, or delegating work, read these files in order:

1. `COMMANDER_STATE.md` - current project truth, active blocker, accepted commits, and next action.
2. `MODEL_TASK_ALLOCATION_RULES.md` - mandatory Sol, Terra, and Luna task boundaries.
3. `COMMANDER_DECISIONS.md` - durable product, privacy, permission, and release decisions.

Do not reconstruct current state from Phase documents unless one of the three files above points to a specific Phase document as evidence.

After a task changes project status, the commander must update `COMMANDER_STATE.md` in the same integration cycle. Add to `COMMANDER_DECISIONS.md` only when a durable rule or boundary changes.

All real marketplace writes remain disabled unless the current state explicitly records a separately approved production trial. Never use production customer data for tests.
