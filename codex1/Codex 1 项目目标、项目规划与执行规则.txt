# Codex 1 项目目标、项目规划与执行规则

## 一、Codex 1 项目角色

Codex 1 负责本项目的 **后端、数据库、平台 API、数据同步、凭证加密、接口日志和数据整合底座**。

项目名称：

AI 多店铺运营与环境管理系统

当前阶段重点：

先做 Naver / Coupang API 数据底座，让系统能够添加店铺、绑定平台 API、测试连接、同步商品、同步订单、同步客服/咨询数据、统计销售额，并为前端和后续 AI 日报提供统一接口。

Codex 1 不负责复杂前端 UI，只需要保证后端接口稳定、数据结构清晰、接口文档可访问。

## 四、核心开发原则

### 1. 所有数据必须绑定 store_id

系统以店铺为中心。

所有业务数据都必须绑定 `store_id`：

```text
平台账号
API 凭证
设备环境
店铺邮箱
商品数据
订单数据
客服咨询
销售额统计
重点邮件
申诉案件
证据文件
同步日志
AI 日报上下文
```

不能出现没有店铺归属的业务数据。

---

### 2. API 凭证必须加密保存

以下信息必须加密保存：

```text
Naver Client Secret
Naver Access Token
Naver Refresh Token
Coupang Access Key
Coupang Secret Key
设备远程账号
设备远程密码
邮箱授权信息
```

前端查询时只返回脱敏字段，不返回明文 Secret。

---

### 3. 平台 API 由后端调用

前端不能直接调用 Naver / Coupang API。

所有平台请求流程：

```text
前端请求本系统后端
→ 后端读取加密凭证
→ 后端解密
→ 后端调用 Naver / Coupang API
→ 后端保存数据
→ 后端返回内部统一格式
```

---

### 4. 第一阶段以只读同步为主

第一阶段主要做数据读取：

```text
读取商品
读取订单
读取客服 / 咨询
读取销售额所需订单数据
读取状态
保存日志
```

平台写入类动作后续再做。

---

### 5. 中文和韩文必须避免乱码

全项目统一 UTF-8。

要求：

```text
源码文件 UTF-8
API JSON 返回 UTF-8
数据库 UTF-8
日志文件 UTF-8
JSON 保存 ensure_ascii=False
CSV 导出使用 utf-8-sig
文件名支持中文和韩文
```

测试数据必须包含中文和韩文。

示例：

```text
店铺名称：韩国美妆1号店
商品名称：SK-II 피테라 에센스 230ml
客户咨询：정품 맞나요? 언제 발송되나요?
邮件标题：[네이버] 판매 상품 증빙자료 제출 요청
申诉类型：정품 소명 자료 제출
```

## 九、同步逻辑规则

### 商品同步

从平台 API 获取商品列表后保存到 `products`。

去重更新依据：

```text
store_id + platform + platform_product_id
```

### 订单同步

从平台 API 获取订单列表后保存到 `orders`。

去重更新依据：

```text
store_id + platform + platform_order_id + product_order_id
```

### 咨询同步

从平台 API 获取咨询数据后保存到 `customer_inquiries`。

去重更新依据：

```text
store_id + platform + inquiry_id
```

### 销售额统计

基于 `orders` 表计算：

```text
今日销售额
今日订单数
按店铺销售额
按平台销售额
取消金额
退货金额
净销售额
```
